For cross-cutting principles and the reasoning behind them (why Home stays quiet, why a preview must share its data source with the real thing, why Fastlane is a separate service, etc.), see `.specify/memory/constitution.md` — that file is authoritative on principles the same way this one is on concrete decisions. ## What we're building

TDC Health: family personal-health-records Android/web app by The Doorstep Clinic (Satkrut Ventures Pvt. Ltd., Pune). Core user: urban family caregiver ("Rohan, 34") managing elderly parents' health. Hook: NFC emergency card. Retention: records timeline + med reminders.

**Current phase: one project, built to production (owner decision, 6 Sep 2026).** The Track A / Track B split is **abolished** — see constitution v3.0.0 §One Standard. There is no demo track, no deferral to a later track, and no `[A]`/`[B→A]`/`[B]` binding class. Every principle binds every feature; every feature is a priority and owns a complete spec-kit set (`spec.md` + `plan.md` + `tasks.md` + checklists).

**Production quality, demo data switchable.** The prototype survives as a single `DEMO_MODE` switch: **off in every build that leaves a dev machine**, may substitute *data* but never *behaviour* (never skips authorization, logging, validation, or invents a state the real system cannot produce), and may never be the only path — if removing it breaks a feature, the feature is unfinished. Edge cases now have to work, not merely not crash.

**Capacity is unchanged: solo dev, ~4h/day.** So "every feature is a priority" means *none is cut to fund another* — the old P0/P1 ladder and cut-from-the-bottom slip rule are repealed. It does **not** mean everything at once: features ship in **dependency order**, one at a time, each to completion.

**Production ≠ every integration live.** ABDM, UHI and payment rails sit behind external gates this project doesn't control (`docs/compliance-baseline.md`: WASA is a precondition for ABDM M1; production ABDM is four gates out). A feature blocked on such a gate names **the gate and its owner**, ships everything on our side of it, and still may not claim the integration exists (Principle VI).

Full specs (Spec Kit format) in `specs/`: `001-tdc-phr-patient-app` (core app spec, includes §4.1 UX loops) · `002-onboarding-router-activation` (onboarding, emergency card, ABHA activation) · `003-abdm-sync-subscription` (ABDM continuous sync — gated on ABDM certification) · `004-seed-data-and-summary` (seed/fixture dataset + PDF field mapping) ·
`012-appointment-booking` (**the live booking spec** — discovery, slots,
confirm, lifecycle, reminders; supersedes `010`+`011`, which are retained as

## Consent model (compliance-critical, do not drift)

- Consent is granted **once, explicitly, in-app, logged, revocable**. The NFC card is a capability token exercising a standing grant — never describe a tap as consent.
- ABDM consent is strictly per-patient; family layer = TDC's own `caregiver_grants`, not ABDM delegation.
- ABHA record inflow = ABDM **subscription** + patient-set auto-approve. See `specs/003-abdm-sync-subscription/spec.md`.

## Banned phrases (code comments, UI copy, docs — everywhere)

"auto consent" · "blockchain"/"Hyperledger" · cipher names in UI ("AES-256", "military-grade") · "ABDM certified" · "we fetch everything" · anything implying card-tap = consent.
**Approved copy:** "encrypted" · "stored only in India" · "every access is logged" · "you control who sees what" · "one-time permission" · "built on India's ABDM framework (integration in development)".

## Architecture

```
TDC Health (Flutter)    TDC Doctor (Flutter, planned)  future clients
   └────────────────────────┴──────────────────────────────┘
                            │ JWT — every app is a client, owns no tables
                            ▼
TDC Core API (Django/DRF + Postgres)  ←—(P1 webhook)— CARE fork HMS (TDC Clinic)
   │ writes denormalized emergency_payload snapshot on profile save
   ▼
Emergency Fastlane (FastAPI, separate uptime budget)
   └─ GET /e/{uid}?ctr&cmac → server-rendered responder HTML (zero JS) + FCM family blast + scan log
```

Fastlane reads the snapshot, never live Core joins — it must survive Core being down.

## Data model (prototype)

`users` · `profiles`(owner FK, relation) · `caregiver_grants`(grantor, grantee, ts, revoked_ts) · `records`(profile, type[Rx|Lab|Discharge|Other], title, file, record_date, source[manual_upload|tdc_hms]) · `medications`(profile, name, dose, times[], stock_count, threshold, status[active|stopped], started_on, ended_on) · `dose_events`(medication, profile, dose_date, slot_time, status[taken|skipped], marked_ts) · `emergency_profiles`(1:1, blood_group, allergies, conditions, abha_no) · `emergency_contacts`(profile, name, phone, relation, priority) · `cards`(uid, profile, sdm_key_ref, last_ctr, active) · `scan_events`(card, ctr, ts, ip, geo, is_test, responder_facility, responder_name, responder_phone, false_call_flagged) · `record_share_grants`(scan_event FK, granted_by, granted_at, expires_at, revoked_at) · `appointments`(profile, clinic FK, doctor FK, slot FK, service_date, period, period_starts_at, token_no, status[requested|booked|declined|cancelled|rescheduled|completed|no_show], decline_reason, cancelled_at, cancelled_by, reschedule_count, rescheduled_from, rescheduled_to, provider_snapshot, created_at) · `specialties`(name, icon_ref, sort_order, is_primary) · `clinics`(source[seed|tdc_clinic|uhi], external_ref, name, address_line, area, city, lat, lng, distance_km, hero_image_ref, rating, typical_wait_min, queue_count, consult_fee_inr, cancellation_window_min, response_window_min, accepts_pay_at_clinic, facility_tags[], faqs, active) · `doctors`(source, external_ref, clinic, name, specialty, qualification, experience_years, hid_masked, is_lead, photo_ref, active) · `slots`(doctor, service_date, period[morning|afternoon|evening], starts_at, ends_at, capacity, booked_count, source) · `payments`(appointment FK, gateway_ref, amount_inr, platform_fee_inr, status, refunded_at) · `access_logs`(actor_user, subject_profile, action[read|write], object_type, object_id, ts, purpose, source_service[core|fastlane]).

`access_logs` is required by constitution Principle XI — and independently by Principle VI, since "every access is logged" is already on the approved-copy list and the Trust screen must not claim it before the table exists. Distinct from `scan_events`: that records card mechanics (counter, replay state), this records who saw what. Keep both.

The four directory tables (`specialties`/`clinics`/`doctors`/`slots`) are **reference data, not PHI** — they are the app's only intentionally unscoped read path, and that is recorded in `specs/012-appointment-booking/checklists/security.md`. If a profile-derived field is ever added to them, Principle X applies and the exemption ends. They live in Core and are served to every client; `source`/`external_ref` are internal and never serialized out. `source = seed` rows are `DEMO_MODE` fixtures; production rows come from TDC Clinic (`tdc_clinic`) or UHI (`uhi`). **`slots.capacity`/`booked_count` is not availability** — availability is the clinic HMS's, and our counter is a cache of it. Booking a token is not a reservation. The production path is a **booking request to TDC Clinic / UHI that can be declined**; no code may treat the flip as a confirmation. (GATE for the `uhi` source: UHI onboarding — owner Adi. `tdc_clinic` has no gate: we own the fork.)

**`appointments.status` says only what we actually know (`012`).** The full production enum is `requested · booked · declined · cancelled · rescheduled · completed · no_show`, with **`lapsed` derived at read time** (never stored, never swept by a job) for the window where a session has passed and no clinic outcome has arrived. **`completed` and `no_show` are clinic-side writes only** — the patient app never asserts an outcome it did not observe: `completed` would claim an unwitnessed event and `no_show` is an accusation. Until the TDC Clinic accept/decline surface exists, `requested`/`declined`/`completed`/`no_show` stay unwritten and `lapsed` covers the gap — that is a `DEMO_MODE`-adjacent shortfall with a named owner, not a design. Copy rule is permanent regardless: **"Booking placed" / "Booked"**, never "confirmed", "reserved" or "held" until the clinic has actually acknowledged.

API base `/api/v1/`: auth/otp (mock OTP `000000` in demo mode) · profiles CRUD · profiles/{id}/records · profiles/{id}/summary.pdf · profiles/{id}/medications · profiles/{id}/emergency · cards link/revoke · clinics (search/filter) · clinics/{id} · clinics/{id}/nearby · clinics/{id}/doctors · doctors/{id}/slots (**returns taken slots too, flagged — `012` renders them struck through, not hidden**) · specialties · profiles/{id}/appointments · POST appointments · appointments/{id}/cancel · appointments/{id}/reschedule. Fastlane: GET /e/{uid} only.

## Working conventions

- Solo dev (Adi), ~4h/day. Prefer boring/already-paid-for. Estimates must respect this ceiling.
- Adversarial review habit: anything touching auth, grants, or Fastlane gets a "how would I abuse this?" pass before merge.
- **Compliance is enforced at generation time, not review time.** Constitution **v3.0.0** — Principles I–XV, **all binding, no classes**. The `[A]`/`[B→A]`/`[B]` markers are removed; a marker surviving in any doc is stale, not a live exemption. The three that bite hardest at code-generation time are unchanged in substance: **X** (every queryset scoped server-side from `caregiver_grants` — unscoped `objects.all()` is a build failure), **XI** (`access_logs` row per PHI access, same transaction), **XIV** (every `# DEMO-MODE` tag names its real path, and an unbuilt real path names its blocking gate **and that gate's owner**, or it is a defect). Features touching PHI/auth/grants/Fastlane/ABDM carry `specs/NNN-slug/checklists/security.md`; ABDM surfaces also carry `abdm.md`. Templates in `.specify/templates/`.
- **`DEMO_MODE` discipline (Principle IV).** One switch, off in every build leaving a dev machine. It substitutes **data**, never **behaviour** — it may return fixture rows; it may not skip authorization, skip logging, weaken validation, or produce a state the real system cannot. If removing it breaks a feature, that feature is unfinished. `seed_demo.py` stays a first-class dev/test fixture and is never shipped as content.
- External compliance *facts* (milestone definitions, WASA scope, Fidelius construction, FHIR IG version pin, DPDP dates) live in `docs/compliance-baseline.md` with sources and a verification date — **not** in the constitution, so version pins rot in one place. Verified 10 Aug 2026. **FHIR pin: R4.0.1 + NRCeS IG v6.5.0 released; v7.0.0 is draft — do not build against it.**
- Docs live in `specs/` (Spec Kit format); this file gets a one-line changelog entry on any locked-decision change.
- **Repo layout is decided, in `docs/repo-structure.md`:** services are **platform-level, not inside `health/`** — `platform/services/core-api/` · `platform/services/fastlane/` (moved out 20 Aug 2026, because a service the doctor app calls cannot live inside the patient app's product directory). `health/` now holds `apps/health/` plus its specs and docs, and is scoped to **the patient client**, not the patient stack. Path-filtered CI with **independent per-service deploys** (a shared pipeline would couple Fastlane's uptime to Core's and make Principle I fiction). No workspace tooling for Track A; no shared Python between the two services — they share a *table*, not a codebase. TDC Doctor and TDC Clinic are each their own top-level product directory (`platform/doctor/`, `platform/clinic/`); TDC Clinic's CARE-fork source additionally stays in its own separate repo entirely (`thedoorstepclinic/tdc-care`), never copied in anywhere — a vendored fork cannot cleanly merge from an actively developed upstream. `platform/clinic/` exists as the specs-and-docs stub (created 30 Aug 2026).
- **Every app is a client (20 Aug 2026, locked):** TDC Core API owns the data. TDC Health, TDC Doctor, and any future client consume it over HTTP and hold **no tables of their own** — no client-local directory table, no local cache presented as data. Directory responses are client-agnostic: no field varies by which app asked, and a different projection is a new endpoint, not a branch inside an existing one. Fastlane is not a counterexample — it is a *reader* of a snapshot table, deliberately not a client (Principle I). Track B, Core becomes the **aggregation point**: it ingests TDC's own facilities from TDC Clinic and external providers from UHI/HFR/HPR and still serves one directory API out.
- Real requirements without a spec yet are staged in `docs/backlog.md` (account recovery, data export, app lock, app-wide Marathi, home vitals logging, Help & Support) — check it before "discovering" a gap. **All of it is in scope**; an entry leaves that file by becoming a `specs/NNN-slug/` directory, not by being reclassified. **Account recovery (§1) is the highest-severity unspecced item** — phone *is* the account, Indian users churn SIMs, and a lost number would mean a permanently lost family health record.
- Stale-doc hygiene: if you encounter Hyperledger-era content anywhere, flag it for deletion — do not incorporate it. Same standard applies to real facility/brand names leaking into seed data or example copy — flag and replace with a fictional one (see `specs/004-seed-data-and-summary/spec.md`).

- 6 Sep 2026: **Owner decision (Adi): the Track A / Track B split is abolished. One project, built to production, every feature a priority with its own space.** This is the largest governance change since the constitution was written, and it touches 32 files. **Constitution → v3.0.0 (MAJOR).** The *Binding Classes* section is deleted and the `[A]` / `[B→A]` / `[B]` markers are stripped from Principles X–XV — **all fifteen principles now bind unconditionally**, and "Track B" is no longer a valid deferral target: a feature blocked by an external gate names **the gate and its owner** instead.
